# Glass Test — тест стеклянного виджета

Текст и предоставленный SVG-логотип. Четыре варианта фона, без погоды и сетевых запросов.

**Это исходники, а не готовый установленный виджет. Сборка Xcode и работа на iOS 27.0.1 пока не проверены.**
Проект подготовлен на основе pookjw/ClearAndBlurredWidgets. Настоящий фон выбирает iOS:
внутренний обход может сработать, быть проигнорирован или сломаться после обновления.
Ни подпись приложения, ни успешная сборка не гарантируют прозрачность.

## 1. Что подготовить на Windows

- Аккаунт GitHub и пустой репозиторий `glass-widget-test`.
- Для бесплатных стандартных macOS-сборок можно использовать Public: исходники будут открыты всем.
- Sideloadly с https://sideloadly.io/ . Следуй его текущей инструкции по компонентам Apple на Windows.
- iPhone и USB-кабель. Apple Account вводится в Sideloadly при подписании, не в GitHub и не в переписку.
- Платное членство Apple Developer для первого теста не требуется.

## 2. Загрузка исходников на GitHub

1. Распакуй ZIP. Открой папку `GlassWidgetTest`.
2. Открой пустой репозиторий в браузере и нажми **uploading an existing file**.
   В непустом репозитории: **Add file → Upload files**.
3. Перетащи **содержимое** папки `GlassWidgetTest`, а не саму внешнюю папку и не ZIP.
4. Нажми **Commit changes**. В корне должны находиться `MyApp.xcodeproj`, `MyApp`, `MyWidget`, `scripts`, `README.md` и `.github`.
5. Проверь, что появился файл `.github/workflows/build-ios.yml`.
   Если браузер пропустил папку `.github`, выбери **Add file → Create new file**,
   введи путь `.github/workflows/build-ios.yml` и вставь в него содержимое одноимённого файла из архива.
   Сохрани через **Commit changes**.

Не загружай сертификаты, пароли, файлы Apple Account или свои личные документы.
Проект не требует GitHub Secrets и не содержит секретов автора.

## 3. Сборка без своего Mac

1. Открой вкладку **Actions**.
2. Выбери **Build Glass Test IPA**. Если GitHub просит включить Actions, включи их.
3. Сборка стартует при загрузке в main/master; вручную — **Run workflow → Run workflow**.
4. Дождись результата. При успехе открой запуск и снизу в **Artifacts** скачай **GlassTest-build**.
5. Распакуй скачанный ZIP. Нужен файл `GlassTest-unsigned.ipa`.

Это пакет без подписи, предназначенный для последующего подписания Sideloadly.
Workflow использует стандартный macOS runner, собирает приложение вместе с расширением,
проверяет наличие расширения и архитектуру arm64. Приватные API не проверяются сборкой.

Если запуск красный: открой **Build and package unsigned IPA**, скопируй первую ошибку
и несколько строк вокруг неё. Артефакт может содержать только `build.log` — это НЕ успешная сборка.
Не пытайся переименовывать ZIP с исходниками в IPA.

## 4. Установка на iPhone

1. Запусти Sideloadly на Windows, подключи телефон кабелем и подтверди «Доверять» на iPhone.
2. Выбери устройство и укажи `GlassTest-unsigned.ipa`.
3. Введи Apple Account в Sideloadly и запусти установку.
4. Если программа предлагает удалить PlugIns/Extensions, **не удаляй их**: там находится виджет.
5. Следуй запросам доверия профилю разработчика и включения Developer Mode на iPhone.
   Обычно это «Настройки → Основные → VPN и управление устройством» и
   «Настройки → Конфиденциальность и безопасность → Режим разработчика».
   Пункт Developer Mode иногда появляется только после первой попытки установки.
6. Открой **Glass Test** хотя бы один раз.

С бесплатным Apple Account подпись действует 7 дней; Sideloadly может обновлять её
автоматически, когда компьютер доступен и телефон подключён по USB или настроенному Wi-Fi.
После истечения подписи приложение и виджет могут перестать работать до обновления.

## 5. Проверка стекла

Оставь обычные цветные иконки: оформление **Default**, не Clear/Tinted.
На домашнем экране: удержание → Изменить → Добавить виджет → **Glass Test**.
Добавь средние виджеты, переключая варианты в галерее:

| Вариант | Что запрашивает |
| --- | --- |
| 01 · Обычный | Тёмный непрозрачный фон, контроль |
| 02 · Прозрачный | Приватный стиль фона 1 |
| 03 · Размытый | Приватный стиль фона 2 + vibrant content |
| 04 · Синий | Тот же стиль 2, сверху полупрозрачный синий градиент |

Для первого сравнения достаточно 01 и 03. Затем попробуй 02 и 04.
Везде один и тот же логотип: исходный чёрный SVG используется как белая маска,
геометрия логотипа сохранена. Есть малый и средний размеры.

Смени обои без изменения проекта и пролистни домашний экран. В рабочем варианте
фон должен соответствовать новым обоям. Скриншоты обоев проект не использует.
Синий градиент сам по себе НЕ доказывает работу стекла.

Если виджеты пустые или фон обычный:
- Открой приложение, нажми «Запросить обновление виджетов».
- Удали виджет с экрана и добавь снова; при необходимости перезагрузи iPhone.
- Убедись, что расширение не было удалено при установке.
- Если не помогло — отправь скриншот вариантов 01–04. Частные методы могли измениться.

## Как устроено

- `MyWidget/MyWidget.swift` — тестовая композиция, четыре варианта.
- `MyWidget/Assets.xcassets/CloudLogo.imageset/CloudLogo.svg` — предоставленный логотип.
- `MyWidget/FooObject.mm` — экспериментальный перехват описаний виджетов.
- `MyApp/ContentView.swift` — инструкция на телефоне.
- `.github/workflows/build-ios.yml` и `scripts/build-ipa.sh` — облачная сборка.

Hook меняет только `MyClearWidget`, `MyBlurWidget` и `MyBlueWidget` в расширении этого
приложения. Он не патчит SpringBoard на диске и не меняет другие приложения.
Добавлены проверки классов/методов, fallback при ошибках декодирования, сохранение
времени жизни архивов и обычный Objective-C вызов `initWithCoder:`. Это снижает часть
рисков падения, но не защищает от несовместимости внутреннего Swift ABI или всех исключений.
`FooObject.mm` должен компилироваться с `-fno-objc-arc`, как в исходном проекте.

Это тест для личной установки. Использование приватных API не соответствует требованиям App Store.

## Проверка перед передачей

Выполнены статические проверки структуры проекта, XML/JSON/SVG, связей виджетов с hook,
синтаксиса shell-скрипта и YAML workflow. Xcode/SDK и iPhone здесь недоступны:
компиляция, нативная вёрстка и фактическое стекло требуют запуска Actions и проверки на телефоне.
